## Problem Statement

The operator runs the control plane in front of a ticket record that grows: every source fetch adds rows, and the machine keeps working on them. Today the plane's state side pays for the whole record on every observation cycle, not just for the tickets that moved. The observation cycle walks the list twice, and every ticket name it writes to a queue line, a hold line, a park line, or a collision line costs a full pass over the entire projection: the whole tickets table, eight batched reads over every identity, and the construction of every ticket row, to read one title. The handoff dispatch pays a full pass for every claimed queue item it starts, for every open-origin item it cancels because a pull request covers its ticket, for every plane-action merge it aims, and for the pull request a settled turn fires. The fire itself pays twice: one full pass to find the ticket and the pull request it acts on, and a second full pass to resolve the position to the pull request it opened. So a record with many tickets keeps the plane heavy on every cycle, even when one agent moves. The operator feels it as a plane that gets slower to name, hold, and start as the record grows, and the machine pays it in per-cycle CPU for work that one ticket needed.

## Solution

The ticket work cycle aggregate gains one scoped read. Given one ticket identity, it answers the ticket's own row, exactly the value the full projection would make for that identity, or the fact that no row stands for it. With the row it carries the ticket's pull request link: the open pull requests that fix the ticket, and the listed pull request the ticket opened. The read answers from targeted reads on that one identity, so it costs a constant number of statements that does not grow with the size of the record.

The per-ticket work stands on the scoped read. The cycle names a ticket from the scoped row instead of a full pass. The dispatch resolves a claimed item, decides a covered cancellation, and aims a plane-action merge from the scoped read. The fire reads the ticket's row and its pull request link once, and resolves the position to the pull request it opened from the linked read instead of a second full pass.

The full projection keeps its place. The visible ticket list and its views keep reading it, because the list rule of ADR 0042 is cross-ticket: a ticket rests behind every open pull request that fixes it, and no read of one ticket can answer that. The two top-up walks keep their one list pass each, so each walk sees the state at the moment it runs. The awaiting walk keeps its shared read, because the Next step derivation reads the rows of the positions it routes to. Nothing the operator sees changes: the same rows, the same names, the same holds, the same starts.

## Implementation Decisions

**The scoped read's interface.** The ticket work cycle aggregate's interface gains one operation: the scoped ticket read, proposed name `ticketOf(identity)`. It returns the scoped ticket read value: the ticket's own row, the same ticket value the full projection would make for that identity, before the list rule withholds it, or the fact that no row stands; and the ticket's pull request link: the rows of the open pull requests that fix the identity, and the identity of the listed pull request the identity opened, or its absence. The row carries everything the per-ticket work reads from a ticket: the title, the state, the memberships, the repository, the handoff, the counts and streaks, the completion, the leftover, the name collision, and the ignore and mute flags. The pull request link is the one cross-cutting fact the ticket's own row cannot answer: a ticket rests behind pull requests that are other tickets, and the fire's position stands on the identity of a listed pull request that is another row.

**What the name rule needs, precisely.** The record name of a ticket is the title of its own row, read before the list rule, or the identity alone when the projection holds no row for the identity. The rule consumes none of the eight batched reads the full projection pays. The earlier suspicion that it consumes the name-collisions read is wrong: that read is the Agent name collision fact of ADR 0107, a different name, and the top-up start gate already reads it per identity. So the rule's input narrows from "the projection" to "the row of this identity, or its absence", and the rule itself changes nothing: the title in quotes, the identity alone where no row stands. Surfaces that already hold a projection, the list lines of the view, the boot line, the checkout record, keep naming from the projection's row for the identity. The one shared rule stands behind both inputs, and the suite's scan keeps refusing a second copy of it.

**The cross-cutting pull request link.** The source fact aggregate gains one narrow named operation, per ticket identity, that answers the pull request link: the open pull request rows that fix the identity, found by the same rule the domain already states, a closing reference to the ticket or a factory head branch prefix on the ticket's key, restricted to pull request rows; and the identity of the listed pull request the identity opened, found by the repository identity and the factory head branch. The operation queries pull request rows, not every ticket row, and it returns identities and rows the ticket work cycle composes into the scoped read. The handoff aggregate gains the per-identity form of its unresolved-attempt fact, beside the global form the list keeps: the row fact of the ticket's own row asks "does this ticket have an unresolved attempt", and the list asks the same question of every ticket. Every other row fact already has a per-identity or a one-identity-batch form on the owning aggregate, and the scoped read calls those with the one identity.

**The call sites that switch to the scoped read.** The observation cycle's per-name read, the helper both the cycle and the dispatch use to name a ticket on a line, which today re-projects the record per name: every queue, routing, restart, merge, and handoff line the top-up walks write, and every hold, park, and collision line the cycle reports. The cycle's reported holds keep their one name per hold, read scoped. The dispatch's own per-name read, used on its queue, start, refusal, and merge lines, switches with it. The per-claimed-item ticket resolution in the claim path, which today takes a full pass and picks the one row, reads the scoped row: the start reads the title, the state, the memberships, the repository, and the source kind from it. The per-open-origin-item cancellation in the covered gate reads the scoped read and asks the covered rule of the row and the link. The plane-action merge read, which today takes a full pass to find the ticket and to find the pull request it merges, reads the scoped read: the row for the ticket, the link for the target. The pickup's checkout gate read, asked only when a row reaches the gate, switches the same way. The settled turn's fire reads the scoped read once: the row for the ticket, the link for the pull request it acts on, and the link's listed identity for the position, so the fire's second full pass goes away with it. The re-fire sweep's per-skip fire inherits the scoped fire through the fire's own switch.

**What the full projection keeps.** The visible ticket list and its views, the ignored and the muted and the detail reads of the view, keep the full projection. The two top-up walks keep their one list pass each, because they enumerate the list, and the list rule is cross-ticket by the decision of ADR 0042. The awaiting walk keeps its shared read, because the Next step derivation reads the rows of the positions it routes to. The re-fire sweep keeps its one enumeration pass, which walks the record looking for the tickets that recorded a skip. The boot's line and the checkout record keep naming from the projection they hold. The projection's fields, its eight batched reads, and its statement count do not move: the list pays the same price it pays today, once per walk, not once per ticket the cycle touches.

**The store and the transaction.** The scoped read is a read. It runs on the aggregate's own scoped store handle for its own row, and it asks the owning aggregates for their facts through their narrow named operations, exactly as the full projection already does. It opens no transaction. The rule of one open write transaction, owned by the aggregate that writes the atomic fact, stands untouched, and the store's scope check, which refuses a statement that names a table the aggregate does not own, keeps the scoped read inside its own tables. The read runs on the same store the cycle's writes commit to, so the cycle reads the state it is standing on, at the moment it reads it.

**The domain rules narrow their input, not their judgment.** The covered rule, the merge and fire target rule, and the name rule keep deciding exactly what they decide: an open ticket that has an open fixing pull request, draft or not, leaves the list while it stays open; the newest non-draft open fixer is the target a merge or a fire acts on; a pull request ticket is its own target; and a ticket wears its row's title, or its identity where no row stands. Their input narrows from "every ticket" to "the identity's row and its pull request link", and the suites that pin each rule's behavior stand on the narrowed input.

## Testing Decisions

A good test here establishes external behavior only, at the two ends of the seam. At the aggregate's interface: the scoped read, asked for one identity, answers the same row value the full projection answers for that identity, in every state the plane decides on: a listed ticket, a ticket covered and withheld from the list, a ticket in flight or awaiting that the handoff record keeps, an ignored ticket, a muted ticket, and a ticket the sources stopped listing, which answers as no row. And the pull request link answers what the full-array rule answered: the open pull requests that fix the identity, the drafts counting toward the covered rule and not toward the target, and the listed pull request the identity opened. At the cycle: the observable behavior stands. The same lines the operator reads, the same pickups, the same refusals, the same holds and parks, the same label writes and positions the fire lands. No test reaches inside the aggregate to check how it reads; the statement count pins are the outside measurement of the read's cost.

The modules and suites that carry the test:

- The state layer suites, on the shared state harness, build real state on a real store. The aggregate's own suite pins the scoped read's row against the projection's row, identity for identity, across the states above, and pins the pull request link against the rule's answer on the full array. The statement-count suite, with its helper that counts the statements a read prepares, pins that the scoped read for one identity costs a constant number of statements on a file of five tickets and on a file of three hundred, the same guard the suite already carries for the full projection and the batched reads, and it pins the full projection's count unchanged, so the list's price does not move. The source fact and handoff state suites pin the two new narrow operations: the pull request link per identity, and the per-identity unresolved-attempt fact beside the global read.
- The name rule suite pins the pair, the title in quotes and the identity alone, on the narrowed input, and keeps its scan that refuses a second copy of the rule anywhere in the plane.
- The coordinator seam suites, the observation suite with its per-command pins and the top-up suite, stand unchanged: they wire the real dispatch module over the same state and the real fire, the way the seam's ADR requires, and they pin the cycle's lines, holds, and pickups. A per-ticket pass that re-projects the record would change the statements a cycle runs, and the suite's pins on what the cycle does catch the behavior split.
- The dispatch suites, including the seeded plane chain that drives the real module through the cycle's port, pin the queue, start, refusal, merge, and cancellation lines, and the claim's resolution of the ticket it starts, on the scoped read.
- The fire suites pin the fire's outcome, its label writes, and its position on the scoped read, and the fixing pull request suite pins the covered and target rules on the narrowed input.

The prior art is the statement-count suite's existing pattern: a file of a named ticket count, a read run under the counting helper, and a pin that the count follows the chunk count, not the ticket count, beside a pin that the batched read answers what the per-ticket read answered. The scoped read's pins take that same shape, and the seam suites take the role the observation suite already plays for the cycle's behavior.

## Out of Scope

- What the full projection contains: its fields, its eight batched reads, and its statement count. The visible list keeps paying the whole-record price, because the list rule of ADR 0042 is cross-ticket, and changing the list's read is a different deepening.
- The herdr side of the work, the process per terminal the plane polls: a separate deepening.
- The refresh a settle takes when the turn's source gives nothing: a separate deepening.
- The shape of the handoff dispatch port: ADR 0130 and ADR 0133 name its calls, and this change adds none.
- The re-fire sweep's own enumeration pass, which walks the record looking for recorded skips: this deepening switches the sweep's per-skip fire, through the fire's own switch, and a targeted skip enumeration is a smaller separate change.
- The per-candidate completion reads the walks already make per identity, and the per-identity batched facts the gates already read with one identity: they are already targeted, and they stand.
- The presentation, the views, and the detail pane: they read what they read today.

## Further Notes

**The name rule, in one precise paragraph.** The record name of a ticket is the title of the ticket's own row, read before the list rule withholds covered rows, or the ticket's identity alone when the projection holds no row for it, the ticket the sources stopped listing, or the one a previous run's attempt names while this run has fetched nothing about yet. The rule never consulted any other ticket, and it never consumed any of the eight batched reads the full projection pays: the suspicion that it rides the name-collisions read confuses it with a different fact, the Agent name collision of ADR 0107, which names the herdr name a start would take, and which the top-up start gate already reads per identity. The rule is one ticket wearing one name across every line of its record, the queue line, the start line, the refusal line, the hold line, and the boot's line, so that a reader who follows one ticket reads one record; it is not a claim that names are unique across the record. Two tickets that share a title wear the same name, and the rule as it stands allows that. The scoped read keeps the rule enforceable for one identity by answering exactly what the rule asks: the row of that identity, or its absence, and because the read's contract is to answer the same row value the full projection would, a covered ticket is named from its withheld row in both reads, and a departed ticket is named by its identity in both, and no name slips between the two.

**How the per-cycle CPU changes.** Before: the cycle ran two whole-record list passes, one per top-up walk, and on top of that every per-ticket action re-projected the record, a full pass over the tickets table plus the eight batched reads over every identity plus the construction of every ticket row, once per name the cycle wrote, once per claimed item, once per cancelled item, once per merged item, and twice per settled fire. That extra cost scaled with the product of the movers and the record size, so a large record made every cycle heavy, on the cycles where one ticket moved as much as on the cycles where many did. After: the two list passes stand, unchanged, because the list is the operator's view and its rule is cross-ticket; and every per-ticket action reads the one identity it acts on, in a constant number of statements that touch only that identity's rows. The cycle's state-side cost now scales with the tickets that moved, and the record size enters the cycle's cost through the two list passes alone, the price the list owes, paid twice, not once per name and per start. On a record of a thousand tickets where two move, the cycle pays two scoped reads where it paid, beside its two list passes, a full pass per name it wrote and per action it took.
