## Problem Statement

The operator watches the tickets, and the machine works them. On the herdr-core host, the machine's watch grows with the size of its in-flight set. The Observation cycle runs a probe each period: it reads the roster the host lists, and then it reads the record of every terminal the plane holds, one process behind the next. The roster there carries no status word, so the status of each held terminal comes from its record, and the terminals the probe reads are the plane's own: the recorded names of its in-flight Tickets and Consultations on that host, so the poll never reads every terminal on the machine, but the cost still grows with the set. Ten in-flight Agents cost ten record reads in a row, and the slowest probe is the one with the most Agents in flight.

The coordinator schedules the next cycle after the previous one completes, so the real period is the interval plus the cycle's cost, the interval defaulting to five seconds, and the slowest cycle delays the next probe the longest. The operator feels it two ways. An Agent that finished a while ago still shows as working, because the probe that would settle it waited behind the sequential reads and behind the period the overrun stole, and ADR 0084's Agent wait covers the finish but covers nothing of the Missing agent's correction or of the facts the wait does not watch. And a slot just freed by a finished Agent stays unfilled for an extra period, because the Pickup that would fill it runs on the late probe. On the herdr host neither cost stands: the probe is the one list call that carries every Agent (ADR 0006).

## Solution

Two decisions, one per module.

The merged agent reader, the module that answers the cycle's probe, reads all of the plane's held terminal rows in one concurrent batch. The roster read stands, and when it settles, the record reads of the roster's held rows run together, so the probe pays the slowest of them, not the sum. The Agent reader's interface does not move: the same rows, in the roster's order, the same failure semantics.

The observation coordinator, the module that owns the loop's clock, schedules the next cycle at the previous cycle's start plus the interval, clamped to now when that instant is in the past. A fast probe holds the period at exactly the interval. A slow probe steals no time from the next: the next cycle runs at the slow cycle's completion, and the grid re-anchors at the pace the probe keeps. The Agent wait is untouched: a state match still runs a cycle now, and the poll stays the single source of truth.

## Implementation Decisions

**The batched read of the held terminals.** On the herdr-core host, the merged agent reader's probe reads all of the plane's held terminal rows in one concurrent batch. The probe keeps its two steps: the one unscoped roster read, and the record read of every roster row a held terminal stands under. The second step issues as one batch: the record reads of the held rows are all started together, after the roster settles, and all awaited together, instead of one behind the next. The rows come back in the roster's order, and the merged list, the seat count, the failure badge, and the identity rule read them the way they read today's sequential list (ADR 0142). The batch is a no-op when the roster lists no held row. On the herdr host the probe is the herdr half's single list call (ADR 0006), and the half reads the terminals the run's own handoffs put on herdr-core, empty when none.

**The Agent reader's interface moves nothing.** The probe's contract is the Agent reader's interface: the same rows, in the roster's order, the same answers on failure. A roster the host does not answer is the probe's error on the herdr-core host, where the observation holds, and the stated gap beside the standing herdr half on the herdr host, where the list stands. A record that does not answer leaves the terminal present with an unknown status: the plane restarts no Agent it cannot read. A terminal the host lost, killed or crashed with no exit code, drops its row, so the Missing marker reads it and the wake's no-settle stands beside it. No new seam opens: the process spawning already runs through the command runner, and the test counts the runner's commands.

**The period holds its interval.** The coordinator schedules the next cycle at the previous cycle's start plus the interval, clamped to now when that instant is in the past. Today it schedules from the completion, so the real period is the interval plus the cycle's cost, and every late cycle steals its overrun from the next probe. From the start, a fast cycle holds the period at exactly the interval: each cycle's next stands at its own start plus the interval, whatever the cycle cost, so the grid drifts not at all. A slow cycle that runs past its slot steals nothing: the next cycle runs at the slow cycle's completion, and the grid re-anchors on that cycle's own start, so the period returns to the interval the moment the probe keeps the pace again, and no cycle owes a catch-up. A timer fire that meets a cycle already in flight runs no cycle of its own: it holds that in-flight cycle's start as the grid anchor, so the next cycle stands at the in-flight cycle's start plus the interval, clamped to now. The interval itself stands as it stands: the loop policy's named interval where the policy names one, the config's poll setting otherwise, derived each cycle the way the coordinator reads it today.

**The first tick stands.** The boot runs the first cycle immediately, and the first scheduled cycle stands at the boot's start plus the interval, the way the coordinator does today: the first probe lands at boot, and the next lands on the grid, whatever the first cycle costs.

**The wake stands.** ADR 0084's Agent wait moves nothing: the cycle arms one wait per in-flight working Agent beside its stored name, the until set and the budget stand, and only the state match runs a cycle now. The wake's cycle runs beside the timer's grid and reschedules nothing, and the poll stays the single source of truth.

## Testing Decisions

A good test here establishes external behavior only, at the two ends of the seam. At the reader: one probe, asked of the merged reader on the herdr-core host, answers the rows the sequential probe answered, in the roster's order, and fails the way the sequential probe failed. At the coordinator: the cycles land where the grid says they land, on the virtual clock, over the fake command runner. No test reaches inside the reader to check how it orders its reads: on the virtual clock the runner's record of when each command was asked and when it answered is the outside measurement of the batch, and the virtual clock's cycle landing times are the outside measurement of the grid.

The seam is the coordinator's: the observation suite (`test/observation.test.ts`) drives the real coordinator end to end. It stands on the fixture (`test/observation-fixture.ts`), which builds the real module, the real state file, and the pinned virtual clock, and names the poll interval the loop runs on; the commands run on the fake command runner (`test/fake-runner.ts`), which records every command it is asked to run, in order, the order the commands answered, and how many ran at once.

- On the herdr-core host, one probe issues the roster read and the held terminal reads, and the fake runner's command list records all of them: the count of the reads, and that the terminal reads issue only after the roster settles. On the virtual clock the record shows every terminal read asked before any of them answered, so the runner runs them together, not one behind the next. The rows come back in the roster's order, the way the merged list carries them. A roster the host does not answer reports the probe's error on the herdr-core host and the stated gap on the herdr host, and a record that does not answer reports what today's reader reports: the terminal present with an unknown status, and the lost terminal dropped so the Missing marker reads it.
- On the virtual clock, a cycle that takes longer than the interval schedules its next cycle at the instant the interval would have stood: start plus the interval is in the past, so the clamp stands, and the next cycle runs at the slow cycle's completion, not at the completion plus the interval. A cycle shorter than the interval schedules its next cycle at exactly start plus the interval, so the grid stands on the start, not on the end. The Agent wait's wake still runs a cycle now on the state match, and the poll stays the single source of truth.
- The herdr host's pins stand unchanged: one list call per probe, one process carrying every Agent. The wake's pins stand: the arm on the working report, the until set, the budget, and the no-wake on a miss, a host failure, and a timeout. The Missing agent's flow pins stand: the Startup grace holds the automatic Restart, and the correction lands on the next probe.

## Out of Scope

- The herdr host's single list call (ADR 0006): the probe there is one call that carries every Agent, and the batch reads nothing on that host.
- ADR 0084's Agent wait: the arm rules, the until set, the budget, and the single-source-of-truth standing all stand.
- ADR 0151's scoped ticket read: the state-side reads the cycle's walks take of the ticket record are a separate deepening, and this change moves none of them.
- ADR 0146's one report: the parallel probe changes no report shape, and the report's identity rule and its null roster stand.
- The herdr-core host's own contract: the roster carries no status word, and asking the host to carry one is on the host's side of the seam.
- The refresh a settle takes when the turn's source gives nothing (the review's O3): a separate deepening.

## Further Notes

**Why the period holds, in one precise paragraph.** Today the coordinator schedules each next cycle from the previous cycle's completion, so the real period is the interval plus the cycle's cost, even when the cycle is fast: a fast cycle that finishes early hands its head start to the next period, and the grid drifts one cycle cost later on every cycle. From the start, the schedule stands on the cycle's own start plus the interval. A fast cycle therefore holds the period at exactly the interval: each cycle's next stands at its own start plus the interval, independent of when it finished, so consecutive fast cycles land on a grid that drifts not at all. A slow cycle that runs past its slot steals no time from the next: the instant its start plus the interval names is in the past, the clamp to now stands, and the next cycle runs at the slow cycle's completion. The grid re-anchors on that cycle's own start, so a run of slow cycles runs back to back at the pace the probe keeps, and the period returns to exactly the interval the first time a cycle finishes inside its slot. No cycle owes a catch-up: an overrun buys no extra cycle, and the plane never bursts a run of probes to make up the lost time; it looks again as soon as it can, and then on the grid again.

**The host scope, in one precise paragraph.** The batched read is the probe's core half, and it is scoped by the Agent host resolution the run makes at boot (ADR 0141 through ADR 0144, and ADR 0148). On the herdr-core host the core half is the probe's per-terminal cost: the roster carries no status word, and the record reads of the held terminals are what the probe pays per Agent, so the batch is where the cost stands. On the herdr host the probe is the one list call that carries every Agent (ADR 0006), and the core half reads the terminals that run's own handoffs put on herdr-core, empty when none: the batch is a no-op where the probe is one call. The period rule is not host-scoped: the coordinator schedules the one loop whatever host the run resolved, and a slow probe on either host steals no time from the next probe.

**The records beside this one.** ADR 0146's one report stands: the parallel probe changes no report shape, the report's identity still stands on its content, and the null roster still marks the stale observation beside an unchanged screen. The sibling record ADR 0153 scopes the fire's refresh, the refresh a settle takes when the turn's source gives nothing (the review's O3), and that decision stays separate from this one. ADR 0148, the herdr-core host's adoption of the plane's start into the desktop's space, is on the host's side of the start and touches no probe.
