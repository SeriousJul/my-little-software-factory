## Problem Statement

The operator launches the plane and the ticket list jumps around. As the sources answer one after another, the list is replaced on each answer, on a partial snapshot, and the rows re-order on every replacement: the operator watches the list move several times before it settles, issue #347. And a start the operator just made, a ticket handed off this run, reads as missing for a full poll period. The plane's first herdr probe ran at boot, before any source answered and before the desktop's start had landed in the herdr-core roster, and it found no agent where the state says a ticket is in flight, issue #388. The list the operator reads is not the list that stands: it is a series of partial snapshots, and the missing marker is a probe that landed too early. The refresh coordinator has no fact that says the load it is standing on has settled, so the shell and the Observation coordinator each guess at the moment, the shell per source and the Observation coordinator at boot.

## Solution

The plane settles its initial load before it probes herdr and before the ticket list moves. The refresh coordinator gains the fact that the initial load has settled: it stands when every configured source's first fetch has settled, success or failure. The shell holds the ticket list on the state's boot read until that fact stands, and replaces the list once, from the state that stands, when it does. The plane holds its first herdr probe until the load settles, so the first probe lands on the roster the settled sources make, far likelier to see the just-started agent. A failed first fetch settles the load the way a successful one does, so a source that fails its boot read does not hold the probe open, and the boot does not hang on a source that will not answer. The Startup grace, the next period, and the Agent wait still correct a genuinely missing agent: the first probe is later and likelier to be right, and the correction paths stand behind it.

## Implementation Decisions

**The initial-load-settled fact.** The refresh coordinator's interface gains the fact that the plane's initial load has settled: the promise that resolves when every configured source's first fetch has settled. The initial load is the plane's first read of every source it has been told to read, the fetches that stand on the Plane boot record. A settlement is the fetch's promise resolving, success or failure, and the per-source settlement running: the result is applied to the source fact, the callback fires, and the source's next read is scheduled where the policy stands one. The coordinator owns the fact: it begins with the set of its configured sources, and each source's first settlement marks that source done, and the last to mark resolves the promise. A failed first fetch marks its source done: it records the source's failed read, fires the callback with the failed outcome, and the load advances, so a source that fails its boot read does not hold the load open. When the coordinator stops, the fact resolves, so a held probe or a held list move does not hold the shutdown open. The fact is the one object the shell and the Observation coordinator wait on: the shell waits on it to replace the list, and the Observation coordinator waits on it to run its first cycle.

**The shell holds the list on the boot read.** The shell's callback, the one that today replaces the ticket list and the consultations and ticks the Observation coordinator on every settled source fetch, stands down while the load stands: it records the source's result into the state, and it does not move the list, the consultations, or the Observation coordinator. The list the operator sees between boot and settle is the state's boot read, standing. When the load settles, the shell replaces the ticket list once, from the state that stands then: the tickets the sources that answered carry, joined with the tickets the state held, and the consultations beside them. The replacement reads the state, not the outcome of one fetch, so it reflects the settled load, the sources that succeeded and the sources that failed. The operator's view moves once, when the load settles, and it moves to the settled order.

**The Observation coordinator holds its first cycle.** The Observation coordinator's start runs no cycle while the load stands. It holds its first cycle, and when the load settles the held cycle runs: it reads the roster the sources stand on, and it is the first herdr probe. A tick that lands while the load stands runs no cycle of its own: it marks a cycle owed, and the one held cycle, when it runs, does that work on the state that stands then. So the plane runs no Observation cycle while the load stands, and the first probe lands on the settled roster. The polling schedule that start stands behind it arms only after the first cycle runs, on the settle.

**The held loop policy stands.** The seeded plane of ADR 0129 takes the one-shot boot read, and the one-shot read settles the load the way the polling schedule does: each stub source's first fetch settles, and the last to settle resolves the fact, and the plane's first probe runs on the settle. The frame rig settles the load through the same path: its stub sources settle, and the first probe runs on the settle, so the rig pins the same order the live plane runs. The rig's named operation for settling the sources is the pin of the held probe and the held list.

**The correction paths stand.** The Startup grace, the next period, and the Agent wait stand untouched: they correct a genuinely missing agent the way they do today. The first probe is later than it is today, and it lands on the roster the settled sources make, so it is far likelier to see the just-started agent. Where it does not see the agent, the next probe, or the wake the working report arms, corrects the row. The deepening moves the first probe later; it does not replace the paths that correct a missing agent after the probe lands.

## Testing Decisions

The seams the test stands on are the existing ones. The refresh coordinator's own suite, the observation suite with its per-command pins over the pinned clock, and the seeded-plane frame suites over the frame rig. No new seam is named, and each suite pins the behavior at its own end of the seam.

The refresh coordinator's suite pins the initial-load-settled fact at the coordinator's interface: the fact resolves when every configured source's first fetch settles, on a source set where one succeeds and one fails its first read, and it resolves on the coordinator's stop. It pins the failure semantics the decision names: a failed first fetch settles the load and does not hold the fact open, and the fact does not wait on a fetch the coordinator has stopped. The suite's existing pins for the one-shot boot read and the polling schedule stand, and the fact rides on the same settlement the schedule already fires.

The observation suite, with its per-command pins over the pinned clock, pins the correction through the seam: a stub herdr world whose first roster read lacks a just-started agent and whose next read sees it, where the plane holds its first probe until the load settles, and the ticket's missing display corrects without a restart, the grace pins standing, and the correction landing on the probe that sees the agent. The suite's existing pins for the Startup grace and the Missing marker stand: the grace reads the herdr-core host record, and the marker appears when the start is old enough to read missing, and the pins move only in that the first probe now lands on the settled roster rather than the empty one.

The seeded-plane frame suites, over the frame rig, pin the window. The rig boots the real shell on a seeded plane with stub sources, settles the sources through the rig's named operation, and reads the painted frames. It pins that the painted ticket list stands on the state's boot read until the load settles and moves exactly once after, so a per-settlement move shows up as an extra move it rejects. It pins that the fake runner's command list shows the first herdr probe after the sources' boot reads, not before them, so a probe that lands on the empty roster is caught. It pins the in-flight ticket's presentation in the window: the row wears its state face, the spinner face in the Starting window, and no Missing marker, and the pin moves only in that the Missing marker appears on the first probe after the settle, not before it. The rig's seeded plane takes the one-shot boot read under the held loop policy, and the rig settles the load through its stub sources, so the rig pins the same order the live plane runs.

## Out of Scope

- The boot-sequence module that owns the order of the shell's mounts: the shell mounts its stages in a fixed order today, and the sibling deepening that moves that order into its own module is a separate record. This decision names the order the mounts imply, the boot read and the settled load before the first probe and the first list move, and it does not move the mounts.
- ADR 0152's probe and period: how often the plane probes herdr, and what the probe reads, are the probe's own deepening. This decision holds the first probe later; it changes neither the probe's cost nor its schedule.
- ADR 0153's settlement: how a source's fetch settles, and what a settlement carries, are the settlement's own deepening. This decision names the moment the load settles; it changes what a settlement does, not what it is.
- The frame rig's owned surfaces: the rig drives the shell and reads the painted frames, and the surfaces it owns are its own. This decision pins behavior the rig already drives; it adds no rig surface.
- The Observation cycle's own report, ADR 0146's one report: the cycle still sends one report whose identity carries its change. This decision runs fewer cycles at boot; it changes neither the report's shape nor the rule that stands on it.
- The Startup grace, the next period, and the Agent wait: the correction paths that stand behind the first probe. This decision moves the first probe later; it does not change the grace's window, the period's interval, or the wake's rule.
- The state's boot read: what the plane reads on the last run, and how it stands the ticket list from it. This decision holds the list on that read; it changes what stands on it, not what it is.

## Further Notes

**The window's presentation, in one precise paragraph.** Between boot and settle, the operator reads the ticket list the state's boot read stands, and it does not move. An in-flight ticket from that read wears the face its state answers: a ticket in the Starting window, its handoff claimed and not yet settled or its state handed-off, wears the spinner face in place of its state badge, and a ticket whose state stands as running or awaiting or open wears its state badge. The Missing marker is absent from every row in the window, because no herdr probe has run and no agent report stands to establish that a started agent is gone: the Missing agent is an observation the first probe makes, and the first probe runs only when the load settles, so the marker cannot appear before it. The Startup grace's own rule stands beside this: while the Starting window holds the row keeps its Starting face, and the marker appears only when a probe answers the start is old enough to read missing, which it can do only after the first probe. So the window reads as a stable list on the boot record, in-flight tickets wearing their state faces, and no missing rows: the list the operator reads before the load settles is the state, not a snapshot the first probe has not yet checked.

**Why holding the probe closes the race without replacing the correction paths, in one precise paragraph.** The race of issue #388 is an ordering one: the first herdr probe ran at boot, before any source answered and before the desktop's start had landed in the herdr-core roster, so it read a roster that lacked the just-started agent and the ticket's row read missing, corrected only when the next probe, a full period later, finally saw the agent. Holding the first probe until the load settles moves that first read to after the sources have settled, which is also after the desktop's start has had its time to land in the roster: the first probe now lands on a roster far likelier to include the agent, and the window in which the row can read missing before the first probe shrinks to the gap between the settle and the roster landing, a gap that stands on the desktop's start time, not on the plane's boot time. The deepening does not replace the correction paths: the Startup grace still suppresses the restart a missing fact would earn while it stands, the next period still re-reads the roster, and the Agent wait still wakes the cycle on a working report, so a genuinely missing agent, one the first probe does not see, is still corrected by those paths on the probe or the wake that does. What the deepening removes is the window in which the first probe is certain to be wrong, the window that stood between the plane's boot and the desktop's start, and what it keeps is every path that corrects a missing agent after the first probe lands.
