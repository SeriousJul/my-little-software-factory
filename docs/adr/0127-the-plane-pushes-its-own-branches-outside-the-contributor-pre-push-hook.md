# ADR 0127: The plane pushes its own branches outside the contributor pre-push hook

Status: accepted
Date: 2026-10-09
Records that the control plane's own `git push` commands bypass
`scripts/git-hooks/pre-push`. It changes no check: the hook, its two checks,
and its behind rule stand unchanged for a contributor's push (ADR 0105), and
CI runs the same checks on what the plane pushes.

## Context

[ADR 0105](./0105-the-push-gate-runs-the-three-checks-on-the-merged-tree-and-a-hook-owns-the-two-cheap-ones.md)
put `bun run lint`, `bun run typecheck`, and a behind rule into
`scripts/git-hooks/pre-push`, active in a checkout that set
`core.hooksPath`. The ADR placed that gate at the moment a contributor pushes
work for review. It did not say what happens when the control plane pushes.

The plane pushes two things of its own:

- the ticket's factory branch, carrying only the hold commit the pull request
  open puts under it (ADR 0076), pushed from the Shared checkout;
- a Repository init's first commit (ADR 0075), pushed from a throwaway worktree.

`core.hooksPath` is a repository setting, not a worktree setting, so the hook
runs on those pushes too, and it answers for whatever tree it happens to stand
in. Two measurements on this machine show what that costs.

- The Shared checkout's `node_modules` predated `@types/fontkit`, which landed
  in `6dff8d75` on 2026-10-08. `bun run typecheck` failed with TS7016 on
  `scripts/screen-font.ts`, the hook refused, and every Handoff of a task type
  that opens a pull request failed at its branch push. The operator's warning
  read `pushing the factory branch factory/352-... failed: error: failed to
  push some refs to 'https://github.com/SeriousJul/my-little-software-factory.git'`.
  The plane keeps one line of a failed command, the one a tool marks with
  `error:` or `fatal:` (`failureLine` in `src/lines.ts`), so the hook's written
  reason - `pre-push: bun run typecheck failed` - never reached the operator.
- 18 of this repository's herdr worktrees hold no `node_modules`. In one of
  them, `bun run lint` exits 127 with `biome: command not found`, so the hook
  refuses a push made from a fresh worktree as well.

Neither failure is about the commits being pushed. The hold commit stands on
`origin/<default branch>`, which CI already proved green, and the init commit
is generated bytes the plane wrote into a throwaway worktree.

## Decision

**The plane's pushes name the bypass at the call site, and the bypass is one
constant.**

`src/git-push.ts` holds `BYPASS_CONTRIBUTOR_PUSH_HOOK`, the single flag git
documents for skipping the pre-push hook: `--no-verify`. Every push the plane
builds spreads it into its argv:

- `pushFactoryBranch` in `src/handoff.ts`, the factory branch push of ADR 0076;
- `commitAndPushInit` in `src/repo-init.ts`, the init push of ADR 0075.

**The hook keeps its whole rule for a contributor.** ADR 0105 stands, and the
instruction not to bypass the hook with `--no-verify` still governs the work a
person or an Agent pushes from a checkout. The Agent's own pushes are
contributor pushes and keep the gate.

**The rule is checked from both sides.** `test/handoff.test.ts` and
`test/repo-init.test.ts` pin the argv each flow sends, read from the constant
so a change to the rule moves one place.
`test/git-push-architecture.test.ts` refuses a `"git"` push argv in `src` whose
file does not name the constant, so a third push cannot be written without it.

## Considered options

- **Repair the checkout and change no code.** Rejected: `bun install` restores
  this run, not the rule. Any red lint, red typecheck, or uninstalled
  dependency in the Shared checkout stops every Handoff again, and the warning
  names none of them.
- **Make the hook skip its checks when the dependencies are missing.** Rejected:
  the hook then stops gating without saying so, and the plane still depends on
  a hook a fresh clone never installed.
- **Let the hook detect the plane's push through an environment marker.**
  Rejected: a marker any contributor can set is not a gate, and the plane's
  argv would state nothing about what it skipped.
- **Unset `core.hooksPath` in the plane's checkout.** Rejected: it removes the
  contributor gate from the one checkout that needs it most.
- **Report the hook's reason instead.** Rejected as the fix and settled by the
  decision: once the plane's push names the bypass, no local check stands in
  its path, so there is no hidden reason left to report.

## Consequences

A Handoff no longer depends on the Shared checkout's dependency install, nor on
whether that checkout's lint and typecheck are clean. The checks for what the
plane pushes belong where they already ran: the draft pull request the push
creates gets `bun run lint`, `bun run typecheck`, and `bun run test` from CI.

The plane's push path runs no local check of its own. That is the point of the
decision, and it is worth stating plainly: the plane's push is a bookkeeping
act that makes the branch a pull request can stand on, not a submission of
work.

`docs/development/quality-gate.md`, `docs/development/commands.md`, and
`AGENTS.md` now name who the hook gates. The hook's own header says the same.

What was measured, and what was not, stands in
[the verification record](../verification/contributor-push-gate.md).
