ADR 0160: The plane's boot call stands the Stub herdr world by default ​

Status: accepted Date: 2026-11-14

Records that the plane's boot call, the Seeded plane's boot that the frame rig's boot call rides on, stands the Stub herdr world as the test plane's default runner on the Command runner seam: where the boot builds the fake command runner's pin table today, it builds the world on the test's command runner and the plane's home and checkout paths, and it stands the world beside the pin table. The world holds the herdr side, the git side, and the herdr-core side, and the pin table holds the residual, the GitHub side and the desktop notifications. The named world spec keeps its shape: a case that stands its own world still names it on the plane's runner. Deleting the default returns the pin table to the seat, two runners stand, the agreement between their answers is kept by hand, and the campaign ADR 0132 started stands unfinished. This record stands the default, and it closes the campaign: one deep adapter stands the plane's herdr and git behind the plane's boot call.

Context ​

ADR 0132 cut the Stub herdr world: one deep adapter on the Command runner seam that stands the herdr side, the git side, and the herdr-core side of the test plane's egress, beside the pin table that stands the rest. The world is stateful: a create adds to it, a close removes from it, a start stands an Agent in a pane, and a later read agrees with the command that came before it. The world answers only the command shapes the plane builds, and it refuses every other one, so a shape the plane starts to build that the world never answered shows up as a refusal instead of a silent code zero. The world's own suite pins that surface: its closed-surface block walks the real command shapes the plane builds against a healthy world and refuses any refusal, and every answer shape the world produces is tested against the plane's own readers, the JSON it parses, the codes it reads, and the refusal envelope the handoff takes.

The migration ADR 0132 names stands unfinished at this tree. The world stands four suites: the auto-mode frame suite, the consultation operations suite, the handoff dispatch suite, and the agent input suite. The four share one shape: each stands its world on its own command runner and its own paths, stands the world beside that runner in one egress, and hands the egress to the plane's boot call as the named runner. Three of the four drive the plane without the frame rig, and one drives it through the rig. The frame rig's warm pool reseeds that named runner per test, on the per-test plane's runner, beside the fake command runner of the default path, and the default path at this tree is the table alone.

The other side of the seam stands on the pin table. The plane's boot call builds the plane's own fake command runner, a flat table of exact command answers, and serves it to the App wherever the case names no runner of its own. The boot pins the plane's own git answers on the table, the git-dir fact and the origin URL fact of the plane's healthy checkout, and it seeds the table's empty herdr-core roster and its empty Agent list. The frame suites pin the rest per case. Re-counted on this tree, the 34 frame suites pin 162 herdr vectors, 45 git vectors, and 20 GitHub-side vectors, and they boot the plane 411 times, the largest suites 57, 46, 36, and 32 times. One of the 34 frame suites stands the world, and the remaining 33 stand on the table. The table's coverage and the world's coverage meet on three families: both stand the herdr side, the git side, and the herdr-core side, and only the table stands the GitHub side and the desktop notifications, the two families that lie outside the world's hosts.

The table's herdr and git pins are copies of what the world already answers. The herdr shapes the frame suites pin are the Agent list, the workspace list, create, get, and close, the tab create, close, and list, the pane list, the worktree list and remove, and the Agent start, prompt, read, and wait. The git shapes are the git-dir fact and the origin URL fact, the HEAD fact, the symbolic-ref fact, the branch list, the fetch, the show, and the status. Every one of those shapes stands on the world's surface, and the world answers each from its standing, the workspaces, tabs, panes, and Agents it holds, so a create the plane sends shows up on the next list. The extension ADR 0132's migration asked for, adding to the world's command table the shapes the pin table's pins demand, stands at zero rows: the table's pins demand no command the world does not already hold. What the pins demand of the world is its state, the standing the suite writes, and that is what the table cannot stand: its answer is one row per pin, and it holds no state a later read can agree with. Two runners stand on the same seam, and the agreement between what the table answers and what the world answers is kept by hand, per suite, per pin.

The deletion test says which side is deep. Deleting the world from its four suites returns the pin table to those seats: each suite pins the answers by hand, the way the frame suites do, and the campaign stands back where ADR 0132 found it, with the local builders of the shape ADR 0132 measured at its head. Deleting the default this record stands, the world behind the plane's boot call, returns the pin table to the seat of the test plane as a whole: two runners stand, the world where a suite names it and the table everywhere else, the agreement between them is kept by hand, and the campaign stands unfinished. The table is the shallow side, and the locality the world buys is the reason the campaign cut it: a suite that stands a world reads one standing instead of writing one pin per command per flow.

The landed records stand around the seat. ADR 0157's warm rig pool reseeds the plane's facts per test, the state, the command runner with its fresh command log, the Stub herdr world that stands on it, and the ticket sources' doubles, and it keeps the test renderer, the terminal, the screen model, the App's root, and the frame event witness warm across the file's tests. The pool reseeds whatever runner the boot call stands, and the warm facts never touch the plane's facts, so the decision is order-safe against ADR 0157 in either direction: it stands a different object in the slot the reseed list already names, and the pool's behavior does not move. ADR 0156's waits stand on the renderer's frame passes and read the frame the plane paints on whatever runner it stands, and the boot price ADR 0157 measured stands, because the world is in memory and the boot builds it in the same place the boot built the table, with no file and no process.

Decision ​

The plane's boot call stands the Stub herdr world by default.

  • The default the boot stands. Where the Seeded plane's boot builds the pin table today, it builds the world. The world stands on the test's command runner and the plane's home and checkout paths: it holds a checkout for every repository the plane's config maps to a directory the plane stands, with the repository's clone URL and the worktree root beside the checkout, and it holds no checkout where the config maps none. The world's standing starts empty, no workspace, no tab, no pane, no Agent, and no terminal, the way the table's empty Agent list and its empty herdr-core roster stand today, and the boot read settles the same way: the world's empty standing answers the Agent list and the herdr-core roster the way the table's empty pins answer them.
  • The composition the default keeps. The world and the pin table stand in one egress. The world holds the herdr side, the git side, and the herdr-core side, and the pin table holds the residual, the commands that truly lie outside the world's hosts: the GitHub-side commands and the desktop notifications. The egress routes the model list query to the world, and it keeps one command log for both sides, so a test that reads the external work reads one record.
  • The plane's git pins stand as the world's git commands. The git-dir fact and the origin URL fact the boot pins on the table for the plane's healthy checkout are the world's own answers from the checkout it holds, and the boot pins no more of the herdr side or the git side on the table. A directory the plane stands but holds no checkout for stands as the world's missing-checkout answers, the not-a-repository facts the world already answers.
  • The named world spec keeps its shape. A case that stands its own world, or wraps the runner, names it on the plane's standing exactly as the four suites do today, and the named refinement stands over the default. The default stands only where the case names no runner, and a suite that wants the table's answers against a directory the world holds names the table on its runner, the named spec standing over the default.
  • The world's refusal stands over the table's silence. A shape the plane builds that the world does not hold is a refusal that fails the test. The table's code-zero empty stands only on the residual, where the GitHub side and the desktop notifications answer as they do today.
  • The world's held wait stands over the table's blind hold. A settle state the world holds answers at once, a target the world does not hold is a refusal, and every other target holds, the way the real command blocks, until the world moves the Agent to a settle state. A suite that wants a wait that settles names the Agent in the standing it stands.
  • The frame rig's boot call keeps its shape. The test names no runner, the rig's boot reads the plane's record, and the App stands on the world the boot built. The frame suites migrate one flow at a time, in ADR 0132's rule: a migrated suite's herdr and git pins stand as the world's standing the suite names on the plane's standing, and the suite reads the world's state, not the table's pins. The suite's GitHub-side pins and its notification commands stay on the table.

Considered options ​

  • Keep the pin table as the default, and let the world stand only where a case names it. It loses because the campaign ADR 0132 started stands half done: 33 frame suites stand on the table, two runners stand on the same seam, and the agreement between their answers is kept by hand, per suite, per pin.
  • Stand the world on its own runner and retire the plane's pin table entirely. It loses because the GitHub side and the desktop notifications lie outside the world's hosts, and the plane builds both: retiring the table forces the world to model the hosts it was cut not to hold, and it reopens the world's closed surface against the GitHub side.
  • Extend the world to the GitHub side and the desktop notifications, one world for every command the plane builds. It loses because the world's closed surface is pinned against the herdr, git, and herdr-core commands the plane builds, and a GitHub-side model in the world would stand beside the GitHub side's own stand-in, the one the ticket source seam already reads, and the two would have to agree by hand.
  • Stand the table and the world both by default, and let each suite choose which one it stands. It loses because the choice is the hand-keeping this decision removes, and a default that is two defaults is no default.

Consequences ​

  • The operator sees no change: the decision stands on the test plane alone. The operator's plane runs on the real command runner against the real herdr, the real git, and the real GitHub side. The operator's share is the frame suite's verdict: a shape the plane builds that the world never answered fails the suite instead of passing on a code zero the table owed, and a suite that stands on the world reads the same frame the operator reads.
  • The machine: the test plane's egress answers the herdr side, the git side, and the herdr-core side from the world's standing, and it answers the GitHub side and the desktop notifications from the table beside it. A create, a close, and a start move the standing, and a later read agrees with the command that came before it. One egress, one command log, and one record the test reads.
  • The test: the four suites that stand the world today keep their named spec, and the 33 frame suites that stand on the table migrate one flow at a time. A migrated suite's herdr and git pins stand as the world's standing the suite names on the plane's standing, and its GitHub-side pins and its notification commands stay on the table. The migration is replace-not-layer, in ADR 0132's rule: a pin that stands moves to the standing, and the table's builders a suite stops needing fall away with it. The world's own suite stands untouched, its closed-surface block the pin between the plane's command shapes and the world's answers, and the frame suites' architecture checks keep pinning the shape of the boot call they ride on.
  • The glossary: the Command runner entry stands the world as the default the plane's boot call builds, beside the pin table on the residual, and the Stub herdr world entry gains the note that the plane's boot call stands it by default. This record lands with the implementation, not with this ADR.
